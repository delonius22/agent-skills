# Other Languages

Use this when the target language has no dedicated reference.

1. **Find the baseline.** Identify the current stable toolchain release from the language's official release page (web search if you can). Identify the official or community-standard style guide: Java uses the Google Java Style Guide plus the current LTS JDK; C# uses the .NET coding conventions plus the current LTS .NET; Kotlin uses the Kotlin coding conventions; Swift uses the Swift API Design Guidelines; Ruby uses the Ruby Style Guide with RuboCop; C++ uses the C++ Core Guidelines plus the newest standard the chosen compiler fully supports. Record the choice and source in BUILD_ORDER.md.
2. **Map the docstring format.** Use the language's native doc-comment syntax (Javadoc, XML doc comments, KDoc, DocC, YARD, Doxygen). Keep the labels from `docstrings.md` (file: `Problem:`, `Piece of the problem:`, `Why this comes now:`, `Build order:`, `Previous:`, `Next:`, `Build these in order:`, `Depends on:`, `Depended on by:`, `Spec coverage:`; function: `Problem piece:`, `Why it matters:`, `What:`, `Spec: | Ticket: | Traces to:`, `Build steps:`, `Task:`, `Think about:`, `Expected outcome:`) verbatim inside it. If the format's block tags swallow the text that follows them, put the labelled prose before the tags.
3. **Pick the stub idiom**: the language's own "not implemented" signal, carrying the spec ID (Java `throw new UnsupportedOperationException("S8.1: canonicalize")`, C# `throw new NotImplementedException("S8.1")`, Kotlin `TODO("S8.1")`, Swift `fatalError("S8.1: not implemented")`, Ruby `raise NotImplementedError, "S8.1"`).
4. **Handle imports that only the future body needs** the way that language's compiler and linter require. Prefer one marked, project-level allowance to per-line suppressions. If the compiler rejects unused imports outright, use the language's equivalent of Go's blank-identifier anchors, and say so in the report.
5. **Use the standard project layout** and build tool (Maven/Gradle, dotnet, SwiftPM, Bundler, CMake) with the same companion files: README, BUILD_ORDER.md, TRACEABILITY.md, linter/formatter config, test stubs marked skipped.
6. **Validate**: run the bundled checker with `--lang generic` (it checks the labels in the doc comments), plus the language's compiler or linter if installed.
